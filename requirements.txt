# E. ftfy / regex / prettytable 为什么必须显式列（而不是"上游遗留"）
#
#    全仓库 grep 这三个名字确实都搜不到——但**不在本仓库代码里**，不等于运行时不
#    需要。mmseg 1.2.2 自己的 mmseg/utils/tokenizer.py 里：
#        from ftfy import fix_text
#    以及配套的 regex 用法。这个模块被 SAM / CLIP 之类文本-图像 backbone 的路径
#    触发，而本仓库 backbones/__init__ 无条件导入了 CloudAdapterSamVisionTransformer
#    与 CLIPVisionTransformer。
#
#    关键坑：mmseg 把 ftfy 放在 PyPI 元数据的**可选依赖**里，不是 install_requires，
#    所以 pip install mmsegmentation 不会自动装它 → 运行时 ModuleNotFoundError。
#    这三个包都必须显式写进 requirements。上游原 requirements.txt 列了它们，是对的。
#
# F. 为什么 thop / xformers 是硬依赖（不是"效率优化可选装"）
#
#    import cloud_adapter
#      -> models/__init__ -> backbones/__init__.py:3  from .reins_eva_02 import ReinsEVA2
#           (backbones/__init__ 是**模块级无条件导入**，没有 try/except 包裹)
#      -> reins_eva_02.py:1     from .eva_02 import EVA2
#      -> eva_02.py:22          from .beit import load_checkpoint
#      -> eva_02.py:26          import xformers.ops as xops        <-- 无条件，非 try/except
#      -> backbones/__init__.py:6  from .myreinstoken import MyReinsToken
#      -> myreinstoken.py:9     from thop import profile,clever_format  <-- 无条件
#
#    即：只要 import cloud_adapter，这两个包就必须在。
#
#    xformers 额外还有一个**影响数值**的作用，见 G 节。
#
# G. xformers 与复现性（§3 门禁敏感项）
#    dino_layers/attention.py:21 有 XFORMERS_ENABLED 开关（默认开）。
#    开启时 DINOv2 注意力走 memory_efficient_attention，与 PyTorch 原生
#    scaled_dot_product_attention **数值不完全相同**，会轻微改变训练轨迹。
#
#    74.18 那次实验的环境没有记录，所以无法确定它当年走的是哪条路径。
#    setup.sh 会安装并锁定 xformers 0.0.23.post1；正常导入时 DINOv2 会默认
#    启用它，并打印 "xFormers is available (Attention/SwiGLU/Block)" 提示。
#
#    这不影响实验 01 的内部有效性：B0 与 LS* 跑在同一环境，配对比较成立。
#    只影响 §3 基线 gate 与论文 74.18 的**绝对值可比性**。
#    如果 gate 差了零点几个 mIoU 过不去，先想到这一条。
#    对照实验：XFORMERS_DISABLED=1 重跑 B0_seed42，看 mIoU 漂多少。
#
# H. 其余可选，缺失不影响 CloudSEN12_L1C 训练与评测
#      mmpretrain          -> reins_convnext.py:1，backbones/__init__.py:18 已 try/except
